## mewcode-maven：api-key 读取改为支持项目配置文件

用户请求：让 mewcode-maven（Java 21 + Maven 仿照项目）的 api-key 读取支持项目配置文件，并在配置文件中补 `api_key` 行。

**结论（先查清事实再动手）**：代码链路本已支持——`ProviderConfig.resolvedApiKey()` 优先级为「配置文件 `api_key` > 环境变量（ANTHROPIC_API_KEY / OPENAI_API_KEY）」，YAML 的 snake_case 键由 `ConfigLoader.SnakeCasePropertyUtils` 自动映射到 camelCase 字段（`api_key` → `apiKey`）。真正缺的是配置行。

**改动**：
1. `mewcode-maven/src/main/java/com/mewcode/config/ProviderConfig.java`：重构 `resolvedApiKey()`，提取 `envApiKey()` 兜底方法，补 javadoc 明确优先级。
2. `mewcode-maven/config.example.yaml`：anthropic provider 补 `api_key` 示例行。
3. `mewcode-maven/.mewcode/config.yaml`：openai provider 补 `api_key: ""` 占位行（TODO 注释，留空回退环境变量）。真实 key 待用户填。注意 `.mewcode/` 已在 .gitignore，不会提交。
4. 新增测试 `src/test/java/com/mewcode/config/ProviderConfigApiKeyTest.java`（4 用例）：YAML 解析 api_key、配置优先于 env、空配置回退 env、全缺失返回空串。

**验证**：全量 `mvn test` 78/78 通过（JDK21 + 本机 Maven 3.9.9，E:\codesoft\apache-maven-3.9.9）。

**启动确认**：`mvn package -DskipTests` 生成 `target/mewcode.jar`（97MB fat jar）。在 mewcode-maven 目录下 `java -jar target\mewcode.jar` 可正常启动 TUI（成功读取 .mewcode/config.yaml，显示 qwen3.7-max-2026-05-20 聊天界面）。注意：api_key 为空时启动不报错，发消息时才报 API key not found，需先填 key 或设 OPENAI_API_KEY。

**Bug 修复：build.ps1 在 Windows PowerShell 5.1 下报 NativeCommandError**。原因：脚本顶层 `$ErrorActionPreference = "Stop"`，而 `java -version` 把版本写到 stderr，PS 5.1 在 EAP=Stop 下会把原生命令 stderr 当终止性错误抛出（PS7 已修复）。修复：把 build.ps1 顶层 EAP 改为 Continue（失败仍由 $LASTEXITCODE / throw 兜底），已在 PS5.1 下验证 build.cmd 正常构建。

**配置全局化**：用户想让 MewCode 能在任意目录使用。已创建全局配置 `C:\Users\19179\.mewcode\config.yaml`（复制自 mewcode-maven 项目配置，含阿里云 MaaS provider + 真实 api_key）。验证：从 C:\Users\19179 启动 jar 能正确加载全局配置。MewCode 配置查找顺序：~/.mewcode/config.yaml → <cwd>/.mewcode/config.yaml → <cwd>/.mewcode/config.local.yaml，后层覆盖前层 providers。任何目录启动：`java -jar D:\code\JA\project\others\mewcode-java\mewcode-maven\target\mewcode.jar`，工作目录=启动时所在目录。
