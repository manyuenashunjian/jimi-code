# 01 项目总览与学习地图

## 学习目标

读完本章后，应该能回答：MewCode 的入口在哪里；用户输入如何进入 Agent Loop；模型如何返回文本、思考和工具调用；工具怎样经过权限检查；会话和压缩状态保存在哪里；MCP、SubAgent、Team 与 Worktree 如何协作；Java 与 Go 版本为什么存在以及它们不能简单混用哪些实现。

## 当前源码事实

Java 入口是 `src/main/java/com/mewcode/MewCode.java`。`main` 先按“命令行第一个参数→`MEWCODE_CONFIG`→默认配置层”的顺序确定配置，再调用 `ConfigLoader.load`。配置成功后创建 `MewCodeModel`，把 providers、MCP servers 和 hooks 注入 TUI4J `Program`，最后注册 SIGINT 处理并运行终端程序。Go 入口是 `cmd/mewcode/main.go`，正常模式调用 `config.LoadConfig`、校验 hooks、构造 Bubble Tea model；传入 `--teammate` 时切换为无 TUI 的 teammate worker。

Java 的核心对象关系可以概括为：

```mermaid
flowchart LR
    A[MewCode.main] --> B[ConfigLoader]
    B --> C[AppConfig/ProviderConfig]
    A --> D[MewCodeModel]
    D --> E[Agent]
    E --> F[LlmClient]
    E --> G[ToolRegistry]
    G --> H[PermissionChecker]
    G --> I[McpManager]
    E --> J[ConversationManager]
    J --> K[Session/History]
    E --> L[ContextCompactor]
```

Go 版本具有同样的概念层，但包名不同：`internal/agent`、`internal/llm`、`internal/tools`、`internal/permissions`、`internal/conversation`、`internal/compact`、`internal/mcp`、`internal/worktree` 和 `internal/tui`。Go 的事件通过 channel 返回，Java 使用 `BlockingQueue<StreamEvent>`，这是学习并发模型时最值得比较的差异。

## 业务定位

这不是一个网页聊天机器人，而是一个能够读取代码、搜索文件、编辑文件、执行命令、调用 MCP、创建子 Agent、写计划、保留会话并在上下文接近上限时压缩的终端 coding agent。系统的“业务成功”不是返回一句文本，而是工具动作在权限、工作目录、文件历史和会话恢复约束下完成。

## 分阶段学习

第一阶段只阅读 `MewCode`、`ConfigLoader`、`AppConfig` 和 README，能启动配置解析。第二阶段阅读 `MewCodeModel`、`Agent`、`ConversationManager`，能画出一轮模型调用。第三阶段阅读 `ToolRegistry`、`PermissionChecker`、`Bash`/`ReadFile`/`EditFile`，能说明一次工具调用为什么被允许或拒绝。第四阶段阅读 `ContextCompactor`、`SessionManager`、`MemoryManager` 和 `WorktreeManager`，能解释长会话、恢复和隔离。第五阶段比较 Go 版本并完成复刻实验。

## 术语提醒

- Agent Loop：模型输出工具调用，工具执行结果追加到消息，再请求模型的循环。
- Tool schema：给模型看的参数形状，不等于授权。
- Permission：服务端对工具、路径、命令的实际放行/拒绝。
- Compaction：减少上下文体积，不是删除所有历史。
- Recovery state：压缩后重建文件和技能上下文所需的快照。
- Worktree：为并行 Agent 隔离 Git 工作目录，不是普通临时文件夹。
