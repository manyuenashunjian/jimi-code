# 02 环境、配置与构建

## Java Gradle 版本

根 `build.gradle.kts` 将 Java toolchain 固定为 21，主类是 `com.mewcode.MewCode`，通过 Shadow 插件生成 `build/libs/mewcode.jar`。典型命令是 `gradlew.bat shadowJar`、`gradlew.bat test` 和 `java -jar build/libs/mewcode.jar`。配置层读取用户目录 `.mewcode/config.yaml`、当前目录 `.mewcode/config.yaml` 和 `config.local.yaml`，后者覆盖前者；也可以通过 `MEWCODE_CONFIG` 或命令行传入显式路径。

## Maven 独立版本

工作区根目录 [java-maven](../../java-maven/README.md) 使用 Java 21、Maven Wrapper、`build.cmd`、`pom.xml` 和标准 `src/main/java`/`src/test/java`。不要在 `jimi-code` 根目录运行 Maven，也不要把 Gradle 的 `build/libs` 当作 Maven 的构建证据。Maven 版本配置通过 `config.example.yaml` 复制到 `.mewcode/config.yaml`，支持 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY` 和 `MEWCODE_CONFIG`。

## 配置字段

`providers` 是模型提供商列表；`protocol` 可为 anthropic、openai 或 openai-compat；`base_url` 决定 SDK 请求目标；`api_key` 可以是显式值或环境变量；`model` 是模型名；`thinking` 控制 extended thinking；`mcp_servers` 描述 stdio 或 HTTP MCP Server；`hooks` 定义工具前后事件动作。配置对象通过 SnakeYAML 的 snake_case 属性工具绑定 Java Bean，Go 版本在 `internal/config` 中使用自己的 YAML 结构。

## 首次启动成功证据

成功不只是进程存在。应看到配置加载成功、TUI 绘制、模型 provider 可用、MCP Server 连接结果和第一条流式事件。API Key 错误应在 Client 构造或首次调用时变成清晰的认证异常；YAML 错误应在 ConfigLoader 阶段失败；MCP 单个 Server 失败不应掩盖其他 Server 的工具发现结果。

## 常见错误

Java 21 不存在时 Gradle toolchain 或 Maven Enforcer 失败；Key 为空时 Anthropic/OpenAI client 抛 `AuthenticationException`；base URL 少了协议时网络异常；上下文窗口过小会触发压缩；Windows 下 MCP command 需要 `windowsSafe` 处理；Linux/PowerShell 的环境变量和 `mvnw`/`mvnw.cmd` 不同。排错时先确认当前工作目录，因为配置搜索使用 `user.dir`。

## 安全提醒

不要把真实 API Key 写入版本库或学习文档。`config.example.yaml` 使用占位符；日志只记录 provider、model 和 request id，不记录完整 token。MCP Server 命令可以启动外部进程，必须经过用户确认和工作区审查。
