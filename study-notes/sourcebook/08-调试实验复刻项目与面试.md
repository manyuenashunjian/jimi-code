# 08 调试实验、复刻项目与面试

## 复刻项目建议

可以把 MewCode 复刻为一个更小的 `mini-code-agent`：保留配置加载、一个 LLM client、三个工具（ReadFile、WriteFile、Bash）、一轮 tool loop、确认式权限和 JSONL session。第二阶段加入 MCP；第三阶段加入上下文压缩；第四阶段加入子 Agent 和 worktree。每个阶段都先用 fake LLM 测试，再接真实 provider。

## 最小复刻接口

```java
interface ModelClient {
    Stream<Event> stream(List<Message> messages, List<ToolSchema> tools);
}
interface Tool {
    String name();
    Result execute(Map<String, Object> args, Context context);
}
```

核心循环必须明确：模型输出文本则追加并结束；输出 tool call 则做 schema 校验、权限检查、执行工具、追加 tool result；错误则生成结构化事件；达到最大迭代或 token 预算则终止。不要从一开始复制 200 个类。

## 断点位置

Java：`MewCode.main` 配置解析后、`Agent` 每轮开始、`LlmClient.stream` 返回后、`PermissionChecker` 决策、`ToolRegistry` 查找、`ContextCompactor` threshold、`SessionManager` boundary 写入、`McpManager.connectAll` 和 `WorktreeManager` 创建/清理。

Go：`cmd/mewcode/main.go`、`agent.Agent.Run`、`llm.NewClient`/`Stream`、`tools.Registry.Get`、`permissions.Checker`、`compact.ContextCompactor`、`session` 和 `worktree` 包。

## 面试题

1. 为什么 tool schema 不等于权限？
2. 为什么 LLM 流式调用要用生产者/消费者队列或 channel？
3. 为什么上下文压缩必须保存 boundary 和 RecoveryState？
4. 如何避免工具执行成功但模型超时导致重复？
5. MCP stdio 与 HTTP transport 的故障边界是什么？
6. Worktree 能解决什么并发问题，不能解决什么问题？
7. Java 虚拟线程和 Go goroutine 的取消语义有什么不同？
8. 为什么 API Key 错误、限流、上下文过长和网络错误要分类？

## 验收标准

完成复刻后，必须有 fake provider 测试、工具权限测试、上下文压缩测试、会话恢复测试和客户端取消测试。真实 API、MCP Server、Git worktree 未启动时要明确标记“未实测”，不能把静态阅读当成运行证据。
