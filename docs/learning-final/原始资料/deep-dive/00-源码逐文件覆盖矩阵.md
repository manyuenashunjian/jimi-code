> 统计基线：生产 Java 103 个，测试 Java 14 个，共 117 个。若源码发生变化，应重新生成或人工复核本表。这里的“逐文件覆盖”不是把文件名堆在一起，而是要求学习者对每个文件回答四个问题：它保存什么状态？它暴露什么入口？谁调用它？失败时如何恢复或向上层报告？

## 1. 全局阅读方法

JimiCode 的调用主线可以压缩为：

`JimiCode.main` → `ConfigLoader` → `JimiCodeModel` → `Agent.run` → `LlmClient.stream` → `StreamingExecutor` → `ToolRegistry` / `PermissionChecker` / `HookEngine` → `ConversationManager` → `SessionManager`

这条线不是简单的 MVC，而是一个带有状态回写的 Agent Loop。一次用户输入至少会经历配置选择、Prompt 构建、模型流式响应、工具参数累积、权限决策、工具副作用、工具结果压缩、会话落盘和 TUI 事件消费。源码阅读时，不能只看“方法返回值”，还要追踪以下状态：

- 对话状态：`ConversationManager.messages` 以及消息中的 thinking/tool-use/tool-result 块；
- 模型状态：Provider、协议、上下文窗口、最大输出、缓存 token 和 stop reason；
- 安全状态：`PermissionMode`、规则列表、pending confirmation、Plan 文件；
- 文件状态：`FileStateCache`、`FileHistory`、Worktree session；
- 并发状态：虚拟线程、BlockingQueue、CompletableFuture、后台 SubAgent/Team 通知；
- 可恢复状态：JSONL session、compact boundary、replacement records、memory 文件。

## 2. 分册导航与源码责任边界

- 《01-入口配置消息与Agent主循环》：主程序、TUI 模型、配置对象、Prompt、消息模型、Agent 的每轮执行顺序。
- 《02-LLM适配流式事件与上下文窗口》：Anthropic/OpenAI/兼容协议、SSE、流事件、用量、重试、上下文超限和 max_tokens 恢复。
- 《03-工具权限Hook-MCP与文件变更》：工具注册、延迟工具搜索、Shell/读写/编辑、权限规则、Hook 条件、MCP 包装。
- 《04-会话记忆压缩历史与Worktree》：JSONL 会话、压缩摘要、恢复附件、长期记忆、文件历史、Git 隔离。
- 《05-SubAgent团队Skill任务与TUI》：子 Agent、团队通信、Skill、任务列表、对话框和 UI 事件。
- 《06-依赖库Maven构建与面试原理》：每个 Maven 依赖解决的问题、运行时边界、打包、测试和常见面试题。

## 3. 每个文件必须怎样读

对类或 record，重点看构造参数是不是依赖注入，是否保存可变集合，是否把 Path、线程、进程或网络客户端作为长期资源；对 enum，重点看它是不是状态机或协议词汇；对工具类，重点看输入校验、工作目录解析、权限检查、异常转换和结果截断；对测试，重点看它锁定了哪个不可回归的行为。特别要区分“最佳努力”与“强一致”：JimiCode 的 history、hook notification、replacement record 等部分路径允许持久化失败后继续运行，而会话恢复和工具副作用则要重点检查一致性。

## 5. 从矩阵反推依赖图

第一层是入口和编排：`JimiCode` 只负责把外部参数变成 `AppConfig`，真正的 UI/状态机在 `JimiCodeModel`。第二层是 Agent：`Agent` 维护迭代、上下文压缩和模型流；`StreamingExecutor` 把已完成的工具调用交给具体工具。第三层是横切能力：权限决定工具能否执行，Hook 决定前后置策略，ToolResultBudget 决定结果以完整内容还是摘要进入下一次模型调用。第四层是持久化：SessionManager 保存可恢复的会话，FileHistory 保存可回滚的改动，MemoryManager 和 MemoryScanner 为跨会话知识提供补充。

一个非常容易被忽略的设计是“同一个工具结果有两种视图”：文件和历史中可能保留完整结果，但发送给模型的 `apiConv` 会根据预算替换旧结果。这样做是 token 成本、Anthropic prompt cache 稳定性和审计能力之间的折中。阅读 `ToolResultBudget` 时要同时跳到 `ContentReplacementState`、`ReplacementRecordsIO`、`ConversationManager` 和 `SessionManager`，否则只看一个类会误判它是在删除数据。

## 6. 测试覆盖的反向证据

测试文件不是附属材料，而是行为契约。压缩测试说明摘要、保留尾部和恢复附件是核心语义；配置测试说明非法 YAML、API key 和上下文窗口默认值属于启动契约；Anthropic 用量测试说明不同 SDK response 形态必须归一化；PermissionMode 测试锁定模式映射；SessionManager 测试锁定 JSONL 恢复及 compact boundary；FileMailBox 测试锁定并发/冲突下的文件通信；ToolSearchTest 锁定延迟工具 schema 的检索协议；ToolResultBudgetTest 系列锁定工具结果预算和替换记录的幂等性。

## 7. 逐文件学习检查表

完成一个文件后，至少记录：1）公共入口；2）所有持久状态；3）直接依赖；4）直接调用者；5）正常路径；6）空值、超时、IO、网络、用户拒绝和线程中断路径；7）是否会产生文件、进程、网络或 Git 副作用；8）对应测试；9）可替换的扩展点；10）一个面试问题。对于只有几行的 record/enum，也要写清它为何存在、与 Jackson/SDK/协议的字段对应关系，以及删除它会迫使哪些调用者改用裸 Map 或字符串。
